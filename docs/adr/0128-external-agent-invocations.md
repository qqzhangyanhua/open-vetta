# ADR-0128：在会话里调用外部智能体，终端复用底部面板

## 状态

已接受

## 背景

用户在同一台机器上同时使用 Vetta 和 Grok、OMP、cursor-agent 等编程 CLI。ADR-0119 让这些工具留下的会话出现在左侧「外部工具」里，但只读：Vetta 只能查看，或者生成前情提要后新建一个 Vetta 会话来接续。用户仍然要切到别的终端窗口才能把一条指令交给 Grok，也无法在同一条会话里对照几个工具的输出。

仓库已经有两块相关能力，但都不能原样套用：

- ADR-0125（会话底部面板与交互式终端）提供了多实例、布局树分屏、不淘汰进程的底部面板和 PTY 终端，但它的 shell 终端**切换会话就停止**，快照放在可丢弃的缓存里。
- ADR-0119 规定外部会话只读，「继续」意味着换成 Vetta 执行。

一次交给外部 CLI 的编程任务与这两者都不同：它可能跑好几分钟、正在改文件，有明确的结束和退出结果，执行者始终是对方的进程。

## 决策

1. **术语**：可调用的第三方 CLI 叫[[外部智能体]]，一次发送加一次运行叫[[外部调用]]，接着对方自己的会话往下跑叫[[续跑]]。现有的「智能体」（Vetta 团队成员，创建会话时固定）不扩展到外部 CLI；输入栏上的接收方切换器叫「发给」，与新会话页的团队/智能体选择器区分。
2. **进程形态**：Grok 按 Orca 的方式启动交互式 TUI：`grok -- <第一条>`，进程一直活到用户退出 Grok。后续对话打在 Grok 自己的输入框里，不再从 Vetta 输入栏发第二条。Grok 还在跑时，Vetta 输入栏收起，只留「发给」以便切回 penguin；点「开新会话」会再露出输入栏，用来开另一条 Grok。Grok 退出后再发，用 `grok --resume <id> -- <提问>` 重新打开。OMP 和 cursor-agent 仍是单条指令（`--print`），跑完即退出，追问排队续跑。运行中终端可以接收键盘输入，用来回答 CLI 自己的确认提示，也用来在 Grok TUI 里继续聊。
3. **显示位置**：切到外部智能体时，终端铺满会话主区，输入框留在下面。这是「用 Grok」时用户要看的东西。penguin 会话仍把外部调用放在底部面板，与 shell 终端共用标签栏和分屏。同一外部会话的多次续跑接在同一标签里，用分隔行分开。已结束的外部调用标签没有活着的进程，面板接近上限时可以先回收它们。
4. **模型不可见**：外部调用在 Vetta 会话里单独成为一种条目，不是 `message`，与 `ToolTimingEntry` 同属模型永远看不到的通道。对话里渲染为一张卡片，可以定位到终端里那一次调用的输出。
5. **生命周期与 ADR-0125 的 shell 终端相反**：外部调用由主进程托管，归属发起它的 Vetta 会话，不跟随底部面板组件的挂载与卸载。切走会话继续运行，切回来重新接上；只有关闭运行中的标签（需确认）、删除所属会话、退出应用会停止它。重启后，上次运行中的调用标记为「已中断」。
6. **输出是会话产物**：原始 PTY 输出（含 ANSI）写入该 Vetta 会话的产物目录，随会话删除而删除，不放 `ApplicationCacheService`。单次调用有容量上限，超出时保留开头和结尾，并标明截断了多少字节。清屏和关闭标签只影响视图。
7. **续跑不违反 ADR-0119**：单击外部工具历史仍只打开只读查看。续跑是一个显式动作，只绑定接收方和续跑对象，由用户发出指令后才运行。执行者是对方的 CLI，Vetta 从不写入外部会话文件。续跑在那条外部会话自己记录的目录里运行；目录不存在时不能续跑。
8. **并发**：同一个外部会话同一时刻最多只有一次续跑在运行，这条规则跨 Vetta 会话生效。Grok 的交互式进程还在本会话跑着时，再发送不会新开进程，用户应在终端里打字。「开新会话」仍立刻再开一个 Grok。OMP / cursor-agent 以及跨 Vetta 会话抢同一条外部记录时，其余的排队。
9. **权限不映射**：Vetta 的访问范围和模型选择不适用于外部智能体。切到外部智能体时隐藏这两项，如实提示由对方自己的权限设置决定；不把 Vetta 的访问范围翻译成 CLI 参数，也不代传任何跳过确认的参数。
10. **接入范围**：外部智能体由代码内置的适配器定义（可执行文件、单条指令参数、续跑参数、会话 id 定位），首期为 Grok、OMP、cursor-agent。只有本机检测到可执行文件的才出现在「发给」里，与外部会话导入开关无关。不开放用户自定义命令。远程（SSH）项目首期不支持外部调用，因为 ADR-0124 规定远程工作目录绝不退回本机执行。
11. **新会话页第一条也可以发给外部智能体**：先创建承载用的 Vetta 会话，不向 penguin 发消息，再启动外部调用。「开新会话」只在已经有可续跑的外部会话时出现，避免和新会话页本身的「新会话」撞名。

## 备选方案

- **新建右侧终端区**：与需求稿的版面一致，但要在右侧重做一套多实例、不淘汰、可分屏的注册表，重复底部面板，也就是 ADR-0125 拒绝过的「复用活动面板」路线的变体。
- **常驻交互式 REPL**：对 OMP / cursor-agent 仍拒绝——没有「结束」和退出结果，多次调用会挤进同一个进程。Grok 例外：它的产品就是交互式 TUI（Orca 也这样启动），一次进程就是一条 Grok 会话，用户在对方输入框里追问，不把多条 Vetta 消息塞进同一进程。
- **外部调用的提问和输出进入 Vetta 上下文**：Vetta 可以直接对照结果，但终端输出冗长且混杂控制字符，而且外部工具读到的代码和密钥会原样送到 Vetta 调用的模型。留作后续的显式「引用给 Vetta」动作。
- **按 ADR-0125 切走即停止**：实现最省事，但用户切出去看一眼别的会话，就会让一次正在改文件的任务停在一半。
- **输出放缓存**：沿用 ADR-0125 的快照做法，但「从对话记录回到那一次输出」会在清理缓存后失效。
- **把 Vetta 访问范围映射成各 CLI 参数**：看起来统一，但各 CLI 的权限模型不同，映射出错会悄悄放大权限。

## 后果

- 会话持久化多了一种条目类型。所有读取会话的地方都必须能忽略它，模型上下文构建不得消费它。
- 底部面板里出现两种生命周期规则不同的实例。区分的依据是「有没有明确的结束」，而不是实例类型的名字，新增实例类型时要按这条判据选择。
- 外部 CLI 的升级可能改变单条指令参数或会话文件位置，适配器需要跟着维护；检测不到或调用失败时，要在终端里如实写出原因。
- 首期不支持远程项目、图片输入、`/skill` 和系统通知；这些都可以在现有决策上叠加，不需要推翻本 ADR。
