# desktop 用户主导的全局/项目记忆，与 memory-mode 并存

desktop 用户希望 agent 跨会话记得「我是谁」（家庭、居住地、偏好）和「这个项目在做什么」，并能逐条查看和删除这些记忆。仓库里已有的记忆机制 [[memory-mode]]（ADR-0009）只服务 IM（Claw）：单一 [[MEMORY.md]]，不分范围，由模型通过 `memory` 工具随时增删改，并与 [[session rollover]]、[[日期工作史]] 绑在一起。它的形态解决的是 im-gateway 每条消息冷启动的问题，不适合直接搬到 desktop。

## 决定

新增独立的 desktop [[记忆]]能力，**不依赖、不开启 memory-mode**：

1. **两种[[记忆范围]]**：[[全局记忆]]一份；[[项目记忆]]按项目路径各一份，「对话」默认项目也有一份，挂靠在 [[conversation cwd]]。
2. **结构化[[记忆条目]]**：每条带稳定标识、日期、固定枚举的[[记忆分类]]和[[常驻条目|常驻]]标记，取代 `§` 分隔的纯文本。
3. **写入只有一条路**：用户主动[[生成记忆]] → 模型产出新增或更新两类[[候选记忆]] → 用户逐条审阅、选范围后保存。对话中的模型对记忆**只读**，没有可写的记忆工具，也不在对话结束时自动写入。
4. **存储在用户目录** `~/.vetta/memory/`，永不写进项目仓库；项目移动或删除后的[[失联项目记忆]]保留，由用户处理。
5. **渐进加载**：每个范围各有[[记忆预算]]，超出时只注入常驻条目、按日期从新到旧的条目和分类目录，其余由只读的[[记忆检索]]（关键词 + 分类/范围过滤）按需获取。两个[[记忆开关]]默认打开，只作用于[[交互式 session]]，切换后下一条用户消息生效（同[[个性化懒重建]]）。

复用 memory-mode 的条目代数、事实提取器和提示词渲染，升级为结构化条目；rollover、`JOURNAL.md`、日期运行目录和可写的 `memory` 工具仍只属于 memory-mode。

## Considered Options

- **把 memory-mode 升级成统一模型，Claw 也分全局/项目**：被拒。rollover 和日期目录是 im-gateway 冷启动成本的产物，desktop 不需要；统一会把 IM 专属行为带进 desktop，或者反过来改变 Claw 已上线的行为。
- **模型在对话中随时写记忆（照搬 Claw）**：被拒。desktop 记忆里会有户口、家庭这类私人事实，用户要求每一条都经过自己确认；模型自写还会造成截图里那种重复条目。
- **项目记忆放进项目仓库 `.vetta/`**：被拒。个人事实可能随 git 外泄，SSH 远程项目还需要往远端写文件；代价是项目目录移动后记忆会失联。
- **向量检索**：推迟。关键词加分类过滤足以覆盖第一版规模，向量检索会引入索引、模型依赖和离线可用性问题，日后可以接入 knowledge 运行时。

## Consequences

- 仓库里会长期并存两套记忆：Claw 的 `MEMORY.md`（模型可写、单一范围）和 desktop 记忆（用户审阅写入、两种范围）。新代码需要按入口区分，词汇表里两者互列 _Avoid_。
- 新的只读检索工具不能复用 `memory` 这个工具名，否则会与 memory-mode 的可写工具冲突。
- 项目记忆按路径挂靠，项目改名或移动目录后需要用户手动重新挂靠。
